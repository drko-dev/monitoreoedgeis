# H6D — Real Go RTSP/YOLO pipeline using lab-built FFmpeg (2026-10-14)

**Lab E2E integration PASS, not release ready.**

The explicitly opt-in `TestLabRTSPToRealYOLO` accepts an optional absolute `H6D_LAB_FFMPEG_DECODER` path and passes it through `processing.Config.FFmpegPath`, so the actual FFmpegDecoder launched by the real processing pipeline uses the designated binary rather than PATH. No production default, flags, installer selection or shipping manifest changed.

Tested on Mac M4 with `H6D_LAB_FFMPEG_DECODER=$PWD/runtime-lab/ffmpeg-portable/ffmpeg`, standalone Python 3.11.9, existing local model weights read-only, and bundled Matplotlib `grace_hopper.jpg` image. The loopback RTSP simulator sends H.264 RTP packets generated by **host** FFmpeg (`libx264`), because the minimal portable binary intentionally does not support test fixture encoding. Actual Go RTSP → processing FFmpeg decode → YUV/JPEG → real vision.Sink → Python Worker/YOLO → event callback **uses the portable decoder**. First run PASS: `RTSP_GO_FFMPEG_YOLO_PASS frame=1 detections=1` (person). Repeated with `-count=2`: PASS both. Default `go test ./internal/vision -count=1`: PASS.

The portable `ffmpeg` and `ffprobe` passed the existing dylib closure audit, and independently decoded the H.264 fixture. Binary hashes, build settings and source provenance limitations are documented in `OFFLINE_H6D_FFMPEG_PORTABLE_M4_LAB.md`. The source release PGP signature, legal redistribution terms, codesigning/notarization, full manifest external trust pin, packing, restarts and actual end-to-end no-Internet isolation have **not** been established. Host FFmpeg is still used as a fixture generator in this test; don't claim test independence from host toolchain or readiness. No model files or binaries committed. `RUNTIME_READY=false`, `INFERENCE_READY=false`, `MODEL_REDISTRIBUTION_APPROVED=false`.
