# GEO CAM Edge — Milestone K (Full Edge): K5–K8

This document describes the design, implementation, and operational semantics of the Full Edge subsystems built in Milestone K (IA 2):
- **K5**: GPU / NPU Capabilities and Fallback
- **K6**: Hardware Resource Limits & Protection
- **K7**: Local Event Record & Atomic Disk Persistence
- **K8**: Local Evidence JPEG Capture & Atomic Storage

Core YOLO inference execution (K1–K4) is owned and implemented by another worker. Milestone K5–K8 is decoupled and designed around a clean, type-safe result contract.

---

## 2. K5 — GPU / NPU Capabilities

Configured via `GEOCAM_EDGE_INFERENCE_DEVICE` (`auto`, `cpu`, `cuda`).

1. **CUDA Detection**:
   - Inspects `/dev/nvidia0` and `/dev/nvhost-ctrl`.
   - Checks `nvidia-smi -L` in PATH without cgo.
   - When configured as `cuda` and hardware is absent: executes controlled fallback to `cpu`, logs warning, and increments `cuda_fallback_count`.
   - When configured as `auto`: selects `cuda` if available; otherwise defaults cleanly to `cpu`.
2. **NPU Capabilities**:
   - Does not fabricate runtime support for Coral, Hailo, Jetson, TensorRT, or OpenVINO.
   - Honestly declares runtime status:
     ```json
     "npu": {
       "adapter_ready": true,
       "backend_active": false,
       "status": "NPU ADAPTER/CAPABILITY READY, BACKEND REAL PENDING"
     }
     ```
3. **Physical Host Status**:
   - On the current macOS development host, CUDA hardware is absent.
   - **REAL GPU / NPU HARDWARE VALIDATION = BLOCKED**. Tested with simulated detectors; real execution fell back to CPU cleanly.

## 3. K6 — Hardware Resource Protection

Configured via:
- `GEOCAM_EDGE_MAX_CONCURRENT_INFERENCE` (default: 1, bounds: 1..16)
- `GEOCAM_EDGE_INFERENCE_QUEUE_DEPTH` (default: 32, bounds: 1..256)
- `GEOCAM_EDGE_MIN_FREE_DISK_BYTES` (default: 100MB, bounds: >= 0)
- `GEOCAM_EDGE_MAX_MEMORY_PERCENT` (default: 0.0 / disabled, bounds: 0..100)

1. **Inference Concurrency**: Bounded via non-blocking semaphore (`TryAcquireInference`).
2. **Queue Bounding**: Full queue drops saturated items, logging warnings and incrementing `queue_dropped`.
3. **Disk Guard**: Checks available disk bytes on `GEOCAM_DATA_DIR` prior to writing evidence (`CanWriteEvidence`).
4. **Memory Pressure**: Signals memory pressure when host memory exceeds `GEOCAM_EDGE_MAX_MEMORY_PERCENT`.

---

## 4. K7 — Local Event Persistence

- Stored under: `GEOCAM_DATA_DIR/events/<event_uuid>.json`.
- Directory permissions: `0700`. File permissions: `0600`.
- Write pattern: Writes to temp file (`.event-*.tmp`) in same directory, `Sync()`, `Chmod(0600)`, atomic `os.Rename`.
- No local SQL database (PostgreSQL/MySQL). Pure Go standard library, 100% compatible with `CGO_ENABLED=0`.
- Backlog tracking: Backlog counter primed from disk on startup and kept updated in memory. Survives process restart.

---

## 5. K8 — Local Evidence Storage

- Stored under: `GEOCAM_DATA_DIR/evidence/<candidate_key>/<event_uuid>.jpg`.
- Stored outside release directory.
- Relative path recorded in the event record (`EvidenceRef.Path`).
- SHA-256 checksum calculated and verified on write.
- Atomic publication via temp file and rename.
- Overwrite protection: Rejects collisions (`ErrEvidenceAlreadyExists`).
- Low disk handling: When available disk < `GEOCAM_EDGE_MIN_FREE_DISK_BYTES`, evidence write is skipped, `evidence_failures` is incremented, and error is recorded in `EvidenceRef.ErrorMessage`. **Never panics or crashes**.

## Hito M — Modelo canónico de evento (M1–M6)

K5–K8 already built the one canonical event model (`fulledge.LocalEvent`),
the local YOLO pipeline, the on-disk `EventStore`, and the narrow Edge→SaaS
wire contract (`transport.LocalEvent`). Hito M did not create a second model,
store, or queue — it reconciled and closed real gaps in the existing one.

| Item | Status before M | What M closed |
|------|------------------|----------------|
| M1 — event model | Already canonical since K5-K8 (`LocalEvent`: `event_uuid`, `candidate_key`, `frame_seq`, timestamps, class/type, confidence, bbox, `EvidenceRef` — never a filesystem path over the wire). | No change needed. |
| M2 — timestamp | Already correct: `LocalEvent.SourceTimestamp` comes from `InferenceResult.FrameTimestamp` (the worker's own frame timestamp), never `time.Now()`; RFC3339 normalization happens only at the `transport.LocalEvent.Timestamp` (`occurred_at`) boundary. | Added an explicit end-to-end test (`internal/agent/fulledge_wiring_test.go`) proving `Frame.Timestamp` survives unchanged through `LocalEvent` to the wire. |
| M3 — tenant/site/camera | Already correct: `transport.LocalEvent` has no org/tenant/site/camera fields; `enqueue()` only ever sends `candidate_key` + device identity. `fulledge.LocalEvent.TenantID/SiteID` are Edge-local config values, never sent to SaaS. | No change needed; added a wire-level assertion in the same test. |
| M4 — type/label | **Gap**: `NewLocalEvent` picked the generic `Tipo` ("vehicle"/"persona") over the specific `Label` ("car"/"motorcycle"/"bus"/"truck") the worker (`deploy/vision-worker/backend.py`) already emits, so the more specific label was silently discarded before it ever reached the wire. | `internal/fulledge/events.go`: `Label` now wins over `Tipo` when both are set; `Tipo` remains the fallback. Real classes/`class_id`s unchanged (`person=0`, `car=2`, `motorcycle=3`, `bus=5`, `truck=7`). |
| M5 — confidence | **Gap**: no check that confidence is finite or in `[0,1]` anywhere in the pipeline. | Added `LocalDetection.ValidateConfidence()` (mirrors `BoundingBox.Validate`); both `Service` call sites drop (log + skip, not abort-the-batch) a detection with a non-finite or out-of-range confidence, same pattern already used for invalid bboxes. The raw model score is never rounded. |
| M6 — bbox | Already correct: pixel `x1,y1,x2,y2` internally, validated by `BoundingBox.Validate`; conversion to `x/y/width/height` happens exactly once, at the `transport.LocalEvent` boundary (`internal/agent/fulledge_wiring.go`). | No change needed. |
